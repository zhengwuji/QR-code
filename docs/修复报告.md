### 回退原因（rawQ 装机实测发现的崩溃）

rawQ（10589 全量重命名版）启动即崩：
`IllegalAccessError: 'md.F' attempting to access 'lock.SystemProps2'`（App.<clinit> → Dispatchers → Tasks 链）。

根因：R8 同包类之间大量使用 **package-private**（类级/成员级）访问；能按 `.source` 还原的类被移去语义包后，同包里 **3464 个无法还原的保留类**（R8 synthetic / 无 `.source`）被留在原地，同包访问变成跨包访问 → IllegalAccessError。排查出 **2262 个保留类散落在 251 个被搬空的原混淆包**里，属于系统性炸弹，逐个修不可行。

处理：把含保留类的 251 个原包**整体回退**为 rawP 命名（保留类与同包伙伴重新团聚，恢复已验证布局）；无保留类的干净包保持语义化命名。结构不变量校验：**0 重复声明、0 混装包**（任何含语义化类的包都不再有保留类残留）。

方法/字段名保持混淆名（跨类多态/override 链，改了会断）；Kotlin `@Metadata` 未动（运行时不解析）。完整映射表：`docs/去混淆映射表.json`（4281 条；全量草稿 `docs/去混淆映射表_全量.json`）。

**重要**：StringFog 字符串仍是密文形态（运行时由 `string/StringFog` 解密），这是行为级修复而非明文还原。

Photo Picker 返回 `content://com.google.android.providers.media.module...` URI，原解码链只支持 `file://`：
`Ce/l.d(Uri)` 用 `uri.getPath()` 得到伪路径 → `FileInputStream` 失败返回 null → 解码中断，界面停在 ScanAlbumActivity 无结果。

| # | 文件 | 改动 |
|---|---|---|
| ⑥ | `smali_classes4/Ce/l.smali` | 新增静态字段 `d:Landroid/content/Context;`；整体重写 `d(Uri)`：scheme 为 `file`/null 走原 `FileInputStream` 逻辑，其余 scheme 走 `ContentResolver.openInputStream(uri)`，异常静默返回 null |
| ⑦ | `smali_classes4/.../App.smali` `onCreate()` | super.onCreate() 后 `sput-object p0` 注入应用 Context 到 `Ce/l.d`（进程启动即生效，同时覆盖 `Ce/x:946` 相册路径与 `page/scan/a:506` 扫码页预览路径两个调用方） |
| ⑧ | `smali_classes2/P5/a.smali` `a(String)` | ExifInterface 前置判空 + `File.exists()` 检查，伪路径直接返回 0 度，消除 `FileNotFoundException` 日志污染 |

方案选择说明：交接单推荐 A1（给 Ce/l 加 `e(Context,Uri)` + `f(Context,Uri,I)` 并改 `Ce/x` 调用点），实施时发现 `a(Uri,I)` 有**两个**调用方，第二个（`page/scan/a.j`）没有 Context 参数可传；且 `Ce/x.d` 是 Kotlin suspend 方法，resume 路径上寄存器不可靠。故改用交接单中的 A2 变体（静态 Context + 改 `d(Uri)` 本体），一处修复覆盖全部调用方，零调用点改动。
